# AndroidWorld Benchmark 复现指南

本指南在本地模拟器上复现 Midscene 的
[AndroidWorld benchmark 报告](./android-world-benchmark-report)：20 个 Android
应用中的 116 个程序化任务，由 AndroidWorld 负责任务初始化和结果校验，由
Midscene 的 `AndroidAgent` 负责界面操作。官方报告使用 `Gemini-3.5-Flash`；
本指南默认使用 DeepSeek V4 系列，并保留 Gemini 配置作为对照，因为模型是
你最可能替换的变量。

:::info 关于 AndroidWorld

[AndroidWorld](https://github.com/google-research/android_world) 是 Google
Research 提供的 Android Agent benchmark。它运行在真实 Android 模拟器上，用
20 个真实 Android 应用中的 116 个程序化任务来评估 Agent，并由 benchmark
负责初始化任务和校验结果。任务设计见[论文](https://arxiv.org/pdf/2405.14573)。

:::

## 运行配置

| 字段 | 官方报告取值 | 本指南默认值 |
| --- | --- | --- |
| 模型 | `gemini-3.5-flash`（`gemini` 系列） | `deepseek-flash`（`deepseek` 系列） |
| Midscene 版本 | `1.9.5` | 当前 workspace 版本 |
| DeepThink | on | on（`aiAct` 参数 `deepThink: true`） |
| 重规划上限 | `MIDSCENE_REPLANNING_CYCLE_LIMIT=120` | Agent 参数 `replanningCycleLimit: 120` |
| 设备 | 模拟器（Pixel 6，API 33） | 模拟器（Pixel 6，API 33） |
| 任务集 | `android_world`，116 个任务 | `android_world`，116 个任务 |
| 计分 | Pass@1 / Pass@2 / Pass@3 | 相同（validator 得分高于 `0.5` 为通过） |

DeepThink 是 `aiAct` 的规划模式，用额外的模型调用做任务分解和元素定位；
复杂多步任务更稳定，代价是延迟更高。重规划上限控制 `aiAct` 放弃前最多
重新规划多少次。优先使用 `replanningCycleLimit` 这个 Agent 参数，环境变量
只作为兼容 fallback。

## 前置条件

- 按仓库根 `package.json`（`engines`）准备 Node.js 和 pnpm，然后执行
  `pnpm install`（会自动构建 workspace 各包）。
- 安装 Android SDK，设置 `ANDROID_HOME`，`adb` 在 `PATH` 中可用，并安装
  `ffmpeg`。
- AndroidWorld 需要 Python 3.11 及以上。
- 准备模型 API Key（本指南默认 DeepSeek）。见[支持的模型与配置](./model-common-config)
  和[模型配置](./model-config)。

## 步骤 1：启动模拟器

1. 在 Android Studio 中创建 AVD：机型 **Pixel 6**，系统镜像 **Tiramisu,
   API Level 33**，AVD 名称 `AndroidWorldAvd`。
2. 用命令行启动（不要用 Studio 界面），带上 AndroidWorld 需要的 gRPC 参数：

```bash
EMULATOR_NAME=AndroidWorldAvd # 上一步创建的 AVD 名称
~/Library/Android/sdk/emulator/emulator -avd $EMULATOR_NAME -no-snapshot -grpc 8554
```

3. 确认设备可见：

```bash
adb devices -l
```

## 步骤 2：安装 AndroidWorld 并应用补丁对照表

```bash
git clone https://github.com/google-research/android_world.git
cd ./android_world
pip install -r requirements.txt
python setup.py install
```

固定 AndroidWorld 的 commit（`git rev-parse HEAD`），并按
`packages/android/androidworld-benchmark/stability-patches.md` 应用稳定性
修复和 validator 校准。这两个表格与官方报告对应：浏览器渲染重试、SMS
setup 校验、Expense 数据库等待、OsmAnd 地图预加载，以及 Calendar /
Expense / Markor / Recipe / 亮度 validator 修正。把 AndroidWorld commit 和
应用的补丁列表记在运行证据旁边；未记录的 validator 改动会改变分数的含义。

首次运行前，做一次性的模拟器应用 setup：

```bash
python run.py --suite_family=android_world --perform_emulator_setup --tasks=ContactsAddContact
```

## 步骤 3：配置模型

DeepSeek（本指南默认，Midscene v1.12.0 起支持）：

```bash
export MIDSCENE_MODEL_BASE_URL="https://api.deepseek.com"
export MIDSCENE_MODEL_API_KEY="......"
export MIDSCENE_MODEL_NAME="deepseek-flash"
export MIDSCENE_MODEL_FAMILY="deepseek"
```

Gemini 对照（官方报告配置）：

```bash
export MIDSCENE_MODEL_BASE_URL="https://generativelanguage.googleapis.com/v1beta/openai/"
export MIDSCENE_MODEL_API_KEY="......"
export MIDSCENE_MODEL_NAME="gemini-3.5-flash"
export MIDSCENE_MODEL_FAMILY="gemini"
```

把 `......` 替换为你的 API Key。只有带视觉输入的 DeepSeek-V4 模型能用于
Midscene，`DeepSeek-V4-Pro` 没有视觉输入，不能使用。Planning / Insight 模型
拆分见[模型配置](./model-config)。

## 步骤 4：验证 Midscene Android 连接

```bash
npx --yes @midscene/android-playground
```

Playground 与 `@midscene/android` 共用核心，Playground 里能跑通的操作，
写成脚本行为一致。Device 生命周期规范：每个 Device 实例只能归属于一个
Agent——为每个 `AndroidAgent` 创建独立的 `AndroidDevice`，Agent 结束后不得
复用该 Device。本 harness 已遵守这条规范（每个任务调用
`agentFromAdbDevice`，`finally` 中执行 `agent.destroy()`）。

## 步骤 5：运行 harness

harness 位于 `packages/android/androidworld-benchmark/`：

- `run.ts` —— Node runner（任务循环、断点续跑、Pass@k 汇总）。
- `androidworld_bridge.py` —— stdio 桥，接 AndroidWorld 的任务注册表
  （`initialize_task`、`is_successful`、`tear_down`），问答类任务的答案经
  `env.interaction_cache` 传递，与内置 Agent 的 ANSWER 动作走同一通道。
- `smoke.config.json` —— 3 个任务的冒烟配置。

```bash
cd packages/android/androidworld-benchmark
npx tsx run.ts --config=smoke.config.json
npx tsx run.ts --tasks=ContactsAddContact,ClockStopWatchRunning --rounds=1
npx tsx run.ts --rounds=3 --resume
```

参数：`--tasks=A,B`、`--rounds=1-3`、`--suite=android_world`、
`--output=dir`、`--resume`、`--task-timeout-ms=N`、`--cycle-limit=N`、
`--config=path`。单任务流程：桥的 `init_task` 返回 goal，runner 调用
`aiAct(goal, { deepThink: true })`（`replanningCycleLimit: 120`）；问答类
任务随后用 `aiAsk(goal)` 读取答案并经 `submit_answer` 提交，最后由
`score_task` / `teardown_task` 记录 validator 判定。如果 AndroidWorld 装在
virtualenv 里，用 `MIDSCENE_ANDROIDWORLD_PYTHON=/path/to/venv/bin/python`
指向该 Python。

## 步骤 6：读取结果

- 第 1 轮跑全部选中任务，第 2-3 轮只重试尚无通过记录的任务，与官方报告
  的轮次方案一致。
- validator 得分高于 `0.5` 计为通过。
- Pass@k 的含义：前 k 轮中任意一次通过，该任务计入 Pass@k。
- runner 追加写 `results.jsonl`（支持崩溃后续跑），写 `summary.json`
  （参数、Pass@k、分轮统计），Midscene 原生 HTML 报告在
  `midscene_run/report/` 下。

:::info 跨模型的分数不能直接比较

官方 Pass@1 93.10% 是在 `Gemini-3.5-Flash` 上测得的。同一 harness 下的
DeepSeek 分数流程可比、数值不可比：每次报告分数时，同时写明模型名称、
Midscene 版本、AndroidWorld commit 和补丁列表。

:::

## 常见问题

- `INJECT_EVENTS permission` 报错：确认设备已开启 USB 调试并保持解锁；
  模拟器镜像默认满足该条件。
- 输入被清空或改写：见 [Android 指南](./platforms/android) 的键盘章节
  （`keyboardDismissStrategy`、`imeStrategy`）。
- 安全页面截图全黑：见同一指南的 `screenshotStrategy`。
- scrcpy 回退到 ADB 截图：这是按帧新鲜度触发的 fallback，不是带宽诊断，
  不要仅凭该 warning 去改码率。
